# Structured metadata projection

The repository publishes deterministic JSON-LD at `structured-data/hypotheses.jsonld` so search systems, research software and autonomous agents can discover the same public hypothesis collection without scraping presentation HTML.

## Source of truth

The JSON-LD projection is generated from the canonical public `hypotheses/{OS-TH-####}/hypothesis.json` objects, existing public evidence bindings, and the governed `governance/evidence-relationship-review-exceptions.json` register for known unresolved scientific-review state. It is not a separate scientific record, evidence store, review register, ranking system or publication authority.

The projection is generated by `scripts/render-structured-metadata.js`. CI runs the renderer in `--check` mode so a stale projection or an invalid protected-review binding fails validation.

## Conservative semantics

Each hypothesis is represented as a Schema.org `CreativeWork`, not as a treatment, medical guideline, clinical recommendation or clinically validated intervention. The projection carries explicit machine-readable properties for:

- research classification;
- canonical disease and disease-context state, including unresolved/null context where that is the canonical state;
- evidence stage;
- review state;
- publication class;
- scientific-review requirement;
- governed protected scientific-review requirement and exception count;
- stable human and machine routes to the protected-review state;
- uncertainty level;
- contradictory-evidence status;
- research-priority status, meaning and explanation;
- novelty status and confidence;
- canonical plain-language and Easy Read projection metadata;
- `clinicalUse:false`;
- the research-only boundary.

The protected-review fields are derived from the governed exception register. They expose only whether a hypothesis has unresolved protected-review state, the number of governed exceptions, and stable discovery routes. They do not copy evidence IDs or disputed relationship values into JSON-LD and they do not decide which scientific interpretation is correct.

The Schema.org `about` terms are derived from canonical disease context and target/pathway names. They are not hard-coded patient attributes and must not be interpreted as patient-specific clinical information. The Easy Read URL is derived only from the canonical stable accessibility projection path and does not imply independent Easy Read or accessibility certification.

Public evidence citations resolve only through existing `evidence-bindings/` records with HTTP(S) canonical source URLs.

## Standards boundary

Using Schema.org JSON-LD makes the metadata syntactically discoverable. It does not claim independent certification, indexing acceptance, external standards conformance, scientific peer review or clinical validation. Search engines and external services may interpret structured metadata differently, so the canonical EduLinked research objects and governed review register remain authoritative for repository meaning.

## Privacy and authority

Do not add private source topology, private research notes, patient information, credentials, unpublished restricted evidence or private authority records to the JSON-LD projection. Only deliberately public research fields, public evidence URLs and bounded public review-discovery state belong here.

A protected-review flag or count means only that a known interpretation disagreement remains under attributable human scientific review. It does not accept evidence, resolve the disagreement, alter `clinical_use:false`, or transfer scientific-review, disclosure, publication or clinical-use authority.
